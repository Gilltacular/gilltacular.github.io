Hashing Versus BST

Hashing and binary searches in a tree data structure are very similar. In hashing, inputs are run through a hash function in order to determine the type and location of the item in an array like list. The hash function also provides the functionality to search only a small subset of that list based on the same logic it used to enter a key there. In a binary search tree, each node has two child nodes of which the left node is always smaller than the right. In this way we can follow a path from the root node to determine any possible node in the list. If both have similar elements and can limit the scope of search and sorting to a smaller subset of data based on some parameters. In some ways a hash function is similar to the tree traversal. So how are they different?

When comparing operations on each structure we should start by looking at the differences in behavior of each. In a binary search tree, the keys of nodes must be compared to that of a key to be inserted or searched for. In a hashing algorithm the index of the key is easily found by retracing the logic of the hash function. While these two behavior may seem similar, a binary search tree overhead increases as the length of the key does while overhead for a hash remains constant as it only is bound to the limitations of its hash function. In this way, a hash table beats binary search trees.

Given this breakdown, you may ask if it is so much better though why do we still use binary search trees? While the idea behind hashing can be more efficient it varies depending on factors such as the hash function quality and its ability to account for all possible keys. A perfect hash function for a given situation may win out in runtime over a binary search tree, but one that does not uniformly fit all edge cases may not. Therefore, in specific instances where keys can be quite long and constraints for a hash function can be easily defined a hash table is a good way to go. If this is not the case however, it may be better to fit a binary search tree structure in place as it will not run into the collision problems of an improperly defined hash function. Over a large enough set of data, constant pathing/order excels over linear insertions where data is not preprocessed in some way.
