The Tree, Trie, and Dancing Tree

In computer science, the tree data structure is a lot like a doubly linked list. That is, it is made up of nodes that each have three elements, of which two contain the address to other nodes and one contains the data of the node. However, unlike a doubly linked list, trees are an abstract data type and as such are subject to their own powers and limitations.

Also, unlike a doubly linked list, but similar to the singly linked list, trees are only traversable in one direction. In this way, linked lists are in essence small trees without reference of the second address node. Trees store data in a way that makes it easily searchable.

In a tree structure there is a root node which serves as the starting point for a tree. The tree then applies new nodes under the root node in a hierarchical structure. The division of the data elements within each node and as a whole within the tree structure depends greatly on the type of tree we are creating and how we will work with that data. In a tree, the node directly preceding another is known as a descendant of that node and using the hierarchical structure is therefore referred to as a parent of that node. Nodes that are higher in the tree than others, or parents of parents, are grandparents and those lower than them are children, grandchildren, etc. The last nodes in the tree structure is defined by two empty or NULL address pointers and are referred to as leaf nodes.

One type of tree is called a trie; a combination of the derived structure and the word retrieval a reference to its common use. In a trie strings are stored with a single node for each common prefix (the beginning characters of a string). In this way the string can be stored over an alphabet using the hierarchical ordering to represent paths that create whole words or word suggestions. One example the use of a trie is in spell-checking programs in which a large dictionary of words is needed or in natural language programs in which speech is taken as input for processing.

Another type of tree is the dancing tree. The use of this type of tree is generally restricted to the Reiser4 file system and differs from like structures like that of the B+ tree in that it does not keep an equally balanced node count at all times for any given level of hierarchy. Instead the dancing tree only attempts to balance nodes when writing data to disk. This implementation is inherently faster as the bottleneck in file systems is typically in writing data to the disk itself and not in traversing or modifying the tree. By minimizing the amount of restructuring (balancing) to the most crucial moment and simply keeping the tree unbalanced before then, the dancing tree gains advantage over other self-balancing binary search trees in its particular area of use; namely the Reiser4 file system. One drawback to the behavior of dancing trees is evidenced in the case where a data-write job is not able to complete for whatever reason. In this case data may be harder to recover and more often lost if not used in conjunction with some form of dynamic backup or file versioning and comparison.
